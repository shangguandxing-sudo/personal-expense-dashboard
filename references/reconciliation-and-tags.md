# 对账与分类规则

## 统一字段和金额口径

| 维度 | 保留字段与规则 |
| --- | --- |
| 来源 | 原始文件与工作表、支付渠道、账号别名、扣款账户别名、覆盖区间 |
| 身份 | 支付交易号、商户单号、平台订单号分别存文本，原值与清洗值可追溯。银行卡尾号只能辅助比对。 |
| 时间 | 下单、付款、退款到账、银行记账时间保持各自含义。统一到同一时区后再取日期。中国大陆账单默认按 `Asia/Shanghai`。 |
| 金额 | 人民币金额换算成整数分。原币种、外币金额和人民币入账金额分别保留。跨币种按用户选定的汇率口径换算，缺少汇率时分币种汇总。 |
| 类型 | 消费、退款、转账或划转、收入、未付款或失败、待核。待核项目有独立清单和原因。 |
| 商品 | 平台、店铺、商品或菜品、规格、数量、整单实付，以及是否有可核实的商品分摊金额。 |

支付行、退款行和原订单分别留存。消费金额取成功实付，除非明确确认是该笔实付的一部分，优惠、运费、服务费不额外叠加。退款以实际到账记录为准。若账单同时有「成功退款」汇总字段和独立退款行，两者只能算一次。汇总字段有金额但缺退款流水时，单列待核，除非能独立证实到账金额和归属时期。

净支出 = 筛选后的成功实付 − 筛选后的到账退款。常用口径按付款日计消费、按实际到账日计退款。银行记账日和支付时间不同的情况需要保留。另做「按原订单净额」时，把退款归回原付款周期，并独立标明报表口径。

转账、充值提现、信用卡还款、理财买入、账户互转默认归「资金划转」。房租等商户或个人转账只有在收款人及用途有证据时才转为实际支出。红包平台名称也不能证明收款人。临近时间的另一笔同额转账只能列为线索。

## 对账顺序

1. **同源去重。** 同渠道、账号、交易类型和交易号建立唯一键。缺稳定编号时，用时间、金额、商户和摘要生成候选，并保留同日同额的多笔真实记录。重复导入补空字段，保留用户手工分类。支付宝历史流水的退款编号可能带原交易号前缀，只有格式得到证实时才拆分。
2. **跨源去重。** 微信或支付宝账单和绑定银行卡可能记录同一笔扣款。资金合并统计时，已验证同一笔的消费或退款只计一次，通常用支付明细丰富的一边为主。能从原账单核实的同向交易引用号或商户单号优先。无编号时，卡片别名、金额、方向、时间和商户共同作为候选依据。仅凭同金额同日期不合并。保留银行原行，并记录主记录、核对证据和待判状态。
3. **订单补明细。** 优先按同平台可核实的订单号关联。订单号缺失时，用已知支付方式、实付、秒级下单或付款时间及门店共同复核，并要求候选唯一。仅同平台、同日、同金额的结果列为待核。订单用于补商品、规格、数量和店铺，已关联订单的整单金额不再入账。拆单、合并付款和多商品订单需要原始范围证据，避免强行一对一。
4. **退款配对。** 使用原交易号、退款关联号或唯一可核实的同商户订单号。不同渠道或金额相同的退款不能凭金额配对。允许一次付款对应多笔退款。仅当已配对到账退款合计恰等于原实付时，「隐藏全额退款」同时隐藏付款和全部对应退款。先在全量交易配对，再筛日期。全部时间净支出不变，跨期时单月结果会变。部分退款、退款超额、重复和无法确认配对的记录保留供核对。

无法确认的重叠应同时给出确认小计、待核规模和报表口径。某月没有账单文件、只覆盖部分日期或尚未到期时分别标注。只有确认有覆盖且没有符合条件交易，才显示 ¥0。

## 标签和证据

- **维度独立。** 平台回答「在哪买」，商户和品牌回答「跟谁买」，支付渠道回答「怎么付」，消费类别回答「买来做什么」。渠道为支付宝的淘宝闪购订单，其平台、支付渠道和餐饮分类分别记录。
- **优先级。** 手工指定的分类优先。之后依次采用已核实原订单的商品、支付账单明确写出的商品、可靠商户及平台规则。把规则按具体到宽泛排序。商品信息不足时保留「待分类」或「商品名待补」。记录标签依据，复核后允许修改。
- **商品名显示原证据。** 把「原订单」「账单商品说明」「仅门店名」「仅订单号」分开显示。平台扣款商户、编号和「外卖订单」用于定位，不能充当菜品或商品名称。
- **主题分析。** 咖啡可分饮品、豆粉与冲煮用品，园艺可分植物、盆器、植料、肥料、工具和养护用药。用商品、规格、品牌及门店召回候选，再剔除同词误命中，例如「冰美式精华水」或「咖啡色鞋」。可识别的咖啡店付款可归店铺消费，并说明账单能确认到店还是到商品。标题只有「A 等多件」时，将混合订单单列，避免把整单金额归给某一商品。
- **多人和更新。** 复制规则时只保留可复用的商户别名和分类策略。账号读取和合并从各自账本开始。重复导入或升级模板时，人工分类、原始数据和独立账号身份需可恢复。

## 验收示例

付款 ¥100，之后分两笔到账退款 ¥40 和 ¥60。全历史影响为 ¥0。隐藏全额退款后这三行一起隐藏。若只退 ¥40，消费与退款两行仍显示，全历史净支出 ¥60。若付款与退款跨月，原始两个月各有发生额，隐藏成对记录后两个自然月会分别移除。

一次外卖支付 ¥29，支付宝、绑卡银行和美团原订单各提供一条记录。确认扣款重叠后只计 ¥29，菜品从原订单补入。若同一天实际下单两次且金额都是 ¥29，逐条用交易号和时间核实。
